Checkout Flow

The checkout shortcode renders a three-step form: Customer Details, Order Summary, and Payment Method. All logic lives in public/templates/checkout.php and the bundled JS that talks to OrderController::checkout().

Template anatomy

  • Layout selector: checkout_template applies modifier classes (kitbix-commerce-checkout--default|modern|split) so you can mirror the screenshot’s two-column layout @/wp-content/plugins/kitbix-commerce/public/templates/checkout.php#7-195.
  • Data attributes: data-tax-rate and data-shipping-flat expose the values from Settings → Store. JS recalculates totals in real time.
  • Customer details: Name, email, phone, and address fields are required out of the box (except phone). Use filters if you need to hide them.
  • Payment methods: Radio list is populated from CartService::availableGateways(). Stripe injects its Elements UI inside data-kitbix-commerce-stripe-wrapper when selected.
  • Order summary: The right column renders line items, subtotal, shipping, tax, and total—matching the provided screenshot.

Request lifecycle

  1. Customer edits the form. JS stores cart contents locally and mirrors them in the summary list.
  2. On submit, the script packages customer info, address, cart items, and selected gateway, then POSTs to /kitbix-commerce/v1/checkout (handled by OrderController::checkout()).
  3. Server validates stock, totals, and gateway availability. If Stripe or PayPal is selected, it creates a payment intent/redirect before finalizing the order.
  4. Successful responses trigger receipt emails (if enabled) and empty the cart, then redirect to the configured thank-you page.

Tips & best practices

Tip: Keep tax + shipping values inside Settings → Store, not in the template. The data attributes ensure every checkout instance stays in sync.
Tip: Use the kitbix_commerce_checkout_after_payment_methods hook to add trust badges (as shown in the screenshot) without editing template core.

Common mistakes

  • Forgetting to enable at least one payment gateway—checkout will render “No payment methods available” and all orders will fail.
  • Changing the HTML name attributes (e.g., name="email") and breaking OrderController::checkout() validation.
  • Removing data-kitbix-commerce-checkout from the form; the JS can’t bind submit handlers without it.
Reminder: Never expose secret keys in the template. Stripe’s client config already contains the publishable key via CartService::availableGateways(); keep secrets server-side.
