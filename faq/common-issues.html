Common Issues

Troubleshoot frequent problems in the free Kitbix Commerce plugin: storefront rendering, checkout, addons, analytics, and email delivery.

Storefront not showing products

  • Confirm the page contains a Kitbix shortcode ([kitbix_commerce_products] or [kitbix_commerce_product]). The CSS/JS only loads when those shortcodes are present.
  • Ensure products are “Published” in wp-admin and not filtered out by category slugs in the shortcode attributes.
  • Flush permalinks (Settings → Permalinks → Save) if SEO plugins rewrote kitbix_commerce_product query vars.

Checkout stuck or empty

  • Open the browser console. 403 errors usually mean the REST nonce expired. Regenerate by refreshing the page or disabling aggressive caching.
  • Verify at least one payment gateway is enabled (Settings → Payments). OrderController::checkout() returns “No payment methods available” if the gateway list is empty.
  • Exclude the checkout URL and /wp-json/kitbix-commerce/ path from cache/CDN proxies so POST requests reach WordPress.

Addon doesn’t render

  • Open Kitbix → Addons and ensure the module is toggled on. Most addon renderers bail if AddonRegistry::isEnabled() returns false.
  • Fill required settings: Live Purchase Toast needs at least one recent order, WhatsApp requires a numeric phone number, Shipping Cutoff Clock needs a cutoff time.
  • Check context flags—Shipping Cutoff Clock has show_on_product/cart/checkout checkboxes, WhatsApp respects the “display context” select.

Analytics returning zeroes

  • Analytics queries kitbix_commerce_orders and kitbix_commerce_products. Seed real orders in the selected date range (Last 7 Days by default).
  • Ensure cron/caching plugins don’t block /wp-json/kitbix-commerce/v1/admin/analytics. 403 responses appear in the browser console.
  • Check server time zone (Settings → General). Buckets use the WordPress timezone; incorrect settings make graphs look empty.

Emails not sending

  • Visit Settings → Email & SMTP. Confirm sender fields and notification toggles match your expectations (email_send_customer_confirmation, etc.).
  • If SMTP is enabled, verify host/port/encryption credentials are correct. EmailNotificationService uses PHPMailer and logs failures to error_log.
  • Resend from the order drawer after fixing deliverability to confirm sendCustomerOrderConfirmation() succeeds.

Tips & best practices

Tip: Keep a staging clone with the same theme/plugins so you can replay issues safely before touching production.
Tip: Capture console/network logs when submitting tickets—REST request URLs and status codes drastically reduce debugging time.

Common mistakes

  • Editing Kitbix templates directly instead of using hooks (changes get overwritten during updates).
  • Deleting sample orders/products during QA—analytics, Live Purchase Toast, and Related Products rely on real data.
Reminder: When unsure, clone the site to staging and reproduce the issue there. Production experiments without backups can corrupt orders or inventory.
