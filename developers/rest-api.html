REST API

Kitbix Commerce registers JSON routes under /wp-json/kitbix-commerce/v1. Admin endpoints require WordPress capabilities plus REST nonces; public endpoints power checkout, payments, and storefront data.

Authentication & headers

  • Admin routes (declared in routes/admin.php) check current_user_can('manage_options'). Send X-WP-Nonce: wp_create_nonce('wp_rest') with your cookies.
  • Public routes (/products, /checkout, /payments/*) skip capability checks but still expect a valid REST nonce to avoid CSRF.
  • All controllers call $request->get_json_params(), so set Content-Type: application/json and provide UTF-8 encoded JSON.
  • Construct URLs with home_url('wp-json/kitbix-commerce/v1/...') to stay multisite-safe.

Admin endpoints

Route Controller Summary
GET /admin/products ProductController::index Paginated list (page, per_page, status, search).
POST /admin/products ProductController::store Create products; body mirrors admin editor fields, fires kitbix_commerce_product_saved.
PUT /admin/products/<id> ProductController::update Update fields + categories. Requires id param and nonce.
GET /admin/orders OrderController::index Order list with status/search filters and pagination meta.
POST /admin/orders/<id>/status OrderController::updateStatus Updates order_status/payment_status; triggers notification emails.
GET /admin/categories CategoryController::index Returns category tree + pagination for the React admin modal.
POST /admin/addons AddonsController::update Toggle addons and persist settings using AddonRegistry.
GET /admin/analytics AnalyticsController::index Accepts range presets (24h, 7d, 1m, 6m, 1y, all, custom) plus optional start_date/end_date.

Public storefront routes

  • GET /products → ProductController::publicIndex. Supports page, per_page, search, category.
  • POST /checkout → OrderController::checkout. Body requires customer, items ({product_id, quantity}), payment_method, optional payment_intent_id.
  • POST /payments/{gateway}/initiate|complete|webhook → PaymentController. Used by Stripe/PayPal adapters and custom gateways.

Pagination & errors

  • List endpoints return { items, meta: { total, per_page, current_page, total_pages } }.
  • Validation issues respond with WP_Error (status 422). Permissions → 403. Not found → 404.
  • Keep per_page ≤ 50 and paginate through page values when syncing large datasets.

Tips & best practices

Tip: Mirror controller sanitization (sanitize_text_field, sanitize_key, current_time) in your integrations to avoid 422 errors.
Tip: Run imports/exports through queues (Action Scheduler, cron) to prevent HTTP timeouts.
Tip: Log webhook payloads—Stripe/PayPal will retry when Kitbix returns non-2xx responses.

Common mistakes

  • Omitting X-WP-Nonce on admin requests.
  • Hardcoding domains instead of reading home_url().
  • Sending form-encoded payloads to JSON endpoints.
Reminder: Never expose REST nonces or cookies in frontend bundles. Proxy sensitive calls through WordPress or a server-side helper that can mint nonces securely.
