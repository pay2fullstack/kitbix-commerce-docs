Product Categories

Categories drive storefront filters and breadcrumbs. They are stored in the categories table and synced to products through the category_product pivot.

Category manager anatomy

  • Tree panel: Left-hand column lists every category (name + slug). Clicking an item loads it into the edit form.
  • Form fields: Name, slug, parent selector, description, image URL, and display order map directly to Category::$fillable.
  • + New button: Resets the form for creating a new record.
  • Modal behavior: Triggered from the Products list or product editor sidebar. All actions call REST endpoints in CategoryController.

Create or edit a category

  1. Open the Products screen and click “Manage Categories”.
  2. Enter a Name. If Slug is left blank, sanitize_title() generates one automatically.
  3. (Optional) Choose a parent to build nested navigation. The controller validates against circular references @/wp-content/plugins/kitbix-commerce/app/Controllers/CategoryController.php#70-191.
  4. Set Display Order to control list ordering on the storefront filter.
  5. Save. The modal calls CategoryController::store() or update(), which timestamps and persists the record.

Assign categories to products

The product editor sidebar lists existing categories. Selected IDs are posted back to the API, which filters invalid entries and resyncs the pivot table.

  • Extraction: ProductController::extractCategoryIds() accepts arrays, comma strings, or objects and converts them into valid IDs @/wp-content/plugins/kitbix-commerce/app/Controllers/ProductController.php#201-230.
  • Sync: Category::syncProductCategories() wipes old rows then inserts the new mapping for the product @/wp-content/plugins/kitbix-commerce/app/Models/Category.php#232-259.
  • Front-end: ProductController::appendCategoriesToProducts() attaches category arrays to every API response so the React admin and storefront can display badges and filters @/wp-content/plugins/kitbix-commerce/app/Controllers/ProductController.php#232-249.

Common mistakes

  • Creating duplicate slugs: CategoryController blocks this with a 422 response, so the UI keeps spinning if you reuse a slug.
  • Assigning a category as its own parent or selecting descendants—validation prevents it, but it wastes time.
  • Deleting categories without reassigning products; the pivot cleanup removes links, so products fall out of storefront filters.
Reminder: Always export categories before bulk edits. They aren’t stored in WordPress taxonomies, so default export plugins will miss them.
