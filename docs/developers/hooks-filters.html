Hooks & Filters

Kitbix Commerce leans on standard WordPress actions and filters so you can extend cart, checkout, and admin flows without forking the plugin.

How to work with hooks

  1. Search the plugin for do_action('kitbix_ or apply_filters('kitbix_ to find insertion points.
  2. Register callbacks from a custom (mu-)plugin on plugins_loaded so they load before Kitbix outputs markup.
  3. Inspect the parameters passed to each hook. Controllers typically pass associative arrays for orders, products, or addon definitions.
  4. Bail early when your conditions are not met (e.g., addon disabled, wrong page, insufficient capability).
  5. Document priorities and accepted args. Hooks usually default to priority 10 but you can run earlier/later by adjusting the fourth argument.

Lifecycle hooks

Hook Parameters Source Typical use
kitbix_commerce_product_saved $productId, $payload, $data ProductController::store()/update() Sync product data to external catalogs or bust caches.
kitbix_commerce_order_created $orderId, $order, $payload, $totals OrderController::checkout(), PaymentController::complete() Push new orders to ERPs, trigger fulfillment webhooks, log analytics.
kitbix_commerce_register_addons $registry AddonRegistry::registerDefaultAddons() Register custom addons implementing AddonContract.
kitbix_commerce_addon_enabled (filter) $enabled, $addonDefinition AddonRegistry::normalizeAddon() Force-disable addons for certain tenants or users.

Frontend placement hooks

Storefront templates expose additive regions so you never edit Twig/PHP templates directly:

  • kitbix_commerce_after_product – product footer (Related Products, Q&A, Shipping Cutoff Clock).
  • kitbix_commerce_after_product_details – under price block (Live View Counter).
  • kitbix_commerce_checkout_after_payment_methods – summary area after gateways (Payment Trust Badge, notices).
  • kitbix_commerce_cart_before_table – banner above the cart table.
add_action('kitbix_commerce_checkout_after_payment_methods', 'myplugin_checkout_notice', 20, 3);

function myplugin_checkout_notice($gateways, $settings, $currency) {
    echo '<p class="kitbix-note">' . esc_html__('Orders ship same day before 4 PM.', 'myplugin') . '</p>';
}

Data filters

  • kitbix_commerce_cart_totals – modify totals array returned by CheckoutTotals::calculate() (add fees/discounts).
  • kitbix_commerce_payment_gateways – alter the list of enabled gateways before checkout renders.
  • kitbix_commerce_addon_settings_fields – extend addon settings definitions before they render in the admin.
add_filter('kitbix_commerce_cart_totals', function ($totals) {
    $totals['fees'][] = [
        'label' => __('Cold chain packaging', 'myplugin'),
        'amount' => 4.50,
    ];
    $totals['total'] += 4.50;
    return $totals;
});

Tips & best practices

Tip: Prefix callbacks (myplugin_*) and wrap them in classes so Composer autoloaders can locate them.
Tip: Always pass the $accepted_args value when hooks expose multiple parameters. Many Kitbix hooks pass 3-4 arguments.
Tip: Profile heavy callbacks with Query Monitor—hooks fire on every matching request.

Common mistakes

  • Returning null from filters that expect the original value.
  • Registering hooks conditionally inside templates (they run too late). Register once during plugin load.
  • Assuming addons are enabled. Guard UI blocks with AddonRegistry::isEnabled( 'addon_id' ).
Reminder: Hooks are synchronous. Avoid long-running HTTP calls—queue them asynchronously or use wp_cron for heavy jobs.
