Database Schema

Kitbix Commerce prefixes every table with {$wpdb->prefix}kitbix_commerce_* and creates them via dbDelta migrations inside /database/migrations. Use the table map below before joining or mutating data.

Migration basics

  • Core\Database::migrate() runs on plugin activation and loads each PHP file in database/migrations.
  • Each migration returns a closure that calls dbDelta(). Tables use utf8mb4 + InnoDB collations by default.
  • Addon-specific tables (e.g., Product Q&A) maintain their own version option and rerun installs only when needed.
  • Never rename Kitbix tables manually—future migrations assume the original structure.

Table reference

kitbix_commerce_products
  • id PK, name, slug (unique)

  • Status + stock: status (draft/published), stock
  • Media: image, gallery JSON

kitbix_commerce_orders
  • Monetary columns: subtotal, tax_total, shipping_total, total
  • Status fields: payment_status, order_status
  • Customer columns: customer_name, customer_email, customer_address
 create_orders_table.php Referenced by Order model, Analytics queries, and REST controllers.
kitbix_commerce_order_items order_id, product_id, per-line price + quantity. create_order_items_table.php Used for order timelines and analytics timeline buckets.
kitbix_commerce_meta Generic key/value table with parent, parent_id, meta_key, meta_value. create_meta_table.php Stores addon configuration or product metadata without schema changes.
kitbix_product_qna Addon table: product_id, question, answer, status. ProductQnaInstaller::install() Versioned via option kitbix_commerce_product_qna_db_version.

Working with data

  • Use KitbixCommerce\Core\Database::table('orders') to construct the correct prefixed table name.
  • Models expose helper methods (Order::adminPaginate(), Product::create())—reuse them instead of writing raw SQL where possible.
  • If you must write custom queries, always call $wpdb->prepare() and respect multisite prefixes.
  • Analytics dashboards run aggregate SQL; keep those queries fast by indexing your custom columns the same way.

Tips & best practices

Tip: Mirror Kitbix timestamps by setting current_time('mysql') for created_at/updated_at.
Tip: For analytics/reporting, create SQL views or replica tables rather than joining directly on production orders.

Common mistakes

  • Hardcoding wp_ as the table prefix—always call the Database helper.
  • Deleting rows without cascading to related tables (e.g., removing an order without deleting order_items).
  • Running ALTER TABLE statements on Kitbix tables; changes will be lost on the next migration run.
Reminder: Back up the database before writing scripts. dbDelta migrations expect the default structure; diverging from it may break updates.
